# v0.1.1 release verification

This coordinated patch release publishes the root module and optional Bleve module. Both public versions were verified through the Go module proxy, and the coordinated [GitHub release](https://github.com/goforj/search/releases/tag/v0.1.1) is published.

| Module | Published tag | Minimum Go |
| --- | --- | --- |
| `github.com/goforj/search` | `v0.1.1` | 1.24 |
| `github.com/goforj/search/driver/blevesearch` | `driver/blevesearch/v0.1.1` | 1.25 |

## Changes

- Add secondary SQL indexes for declared scalar capabilities and SQLite's document-ID join, preserving wide IDs and keyword values.
- Preserve missing/null filter complements while exposing indexable scalar comparisons.
- Aggregate scalar facets directly from document projections and share text matching between exact totals and facets. Keep native ranking, sorted pagination, array deduplication, and transaction snapshots intact.
- Preserve raised SQLite facet limits by batching large aggregate requests within the transaction.
- Wait for Redis's initial indexing scan during provisioning and validation, including existing hashes when recreating an index. Preserve context cancellation and deadline identity.
- Publish reproducible million-document benchmarks across all eight drivers, generated SVG graphs, raw samples, and SQL query-plan investigation notes.

## Compatibility and operations

Public APIs, configuration fields, stored document encodings, and minimum Go versions remain unchanged. The Bleve module requires the coordinated root version. The tooling modules and workspace retain their intentional local replacements.

The SQL query improvements work with existing physical layouts and require no rebuild. New secondary indexes apply only to newly provisioned SQL storage. To gain those indexes for existing data, create a fresh namespace, rebuild from the authoritative source, and switch application traffic. Existing layouts remain readable and writable; runtime operations do not migrate them.

Redis provisioning and validation now wait for complete initial indexing. A caller deadline bounds the wait; otherwise the configured timeout also bounds it. Supply a longer provisioning context deadline when deliberately rebuilding a large existing keyspace.

Broad-term SQL facets remain a performance limitation, particularly SQLite's tail latency. The [benchmark methodology](../bench/README.md) records the selective, warmed, single-client workload and its limits. These results do not establish concurrent-load performance.

## Release gates

The current test inventories and source identity are recorded in [unit results](../unit-results.json), [integration results](../integration-results.json), and [driver evidence](../driver-results.json). Required gates include every relevant module's unit, race, and vet checks; real-backend conformance; exactly 100% unit statement coverage; tidy parity; vulnerability scans; stable generated documentation; and a clean consumer of staged module archives with no replacements.

Local candidate validation passed: 1,021 unit tests, 429 integration tests, 100% unit statement coverage across 3,971 statements, race checks, vet, tidy parity, and two stable documentation generations. Root and Bleve scans using govulncheck v1.9.0 on Go 1.27.3 found no vulnerabilities. A clean consumer downloaded both staged v0.1.1 module archives into a separate cache and passed with race detection, `GOWORK=off`, and no replacements. [CI](https://github.com/goforj/search/actions/runs/42721387375) and [Security](https://github.com/goforj/search/actions/runs/42721387451) passed on release commit [5ed4a51](https://github.com/goforj/search/commit/5ed4a5148e4b3e5993c1617a851ae852ce37b274) before tagging.

The public release check must use the public module proxy, normal checksum verification, and a module cache separate from staged candidate archives. Publish the root before the Bleve tag, verify each module independently, then run `make release-check v0.1.1`. Create one coordinated GitHub release after verifying both tags.

## Public verification

Both `v0.1.1` and `driver/blevesearch/v0.1.1` resolve to commit `5ed4a5148e4b3e5993c1617a851ae852ce37b274`. The root version was verified before publishing the Bleve tag. Each public module was downloaded through `https://proxy.golang.org` using normal `sum.golang.org` verification in a new module cache, separate from the staged candidate cache.

The public `scripts/check-public-release.sh v0.1.1` consumer passed with race detection, `GOWORK=off`, and no replacements. The GitHub release is public, marked Latest, and was published on November 9, 2026. No existing tags were moved.
